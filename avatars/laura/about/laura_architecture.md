# Laura System Architecture

**Owner:** Product/engineering
**Applies to:** Current Laura backend and live meeting workflow
**Last reviewed:** 2026-07-03

## What Laura is

Laura is a callable AI process avatar. She joins a Zoom, Google Meet, or
Microsoft Teams meeting through Recall.ai, listens to the live transcript, and
answers when addressed. The answer is generated by the backend brain from
Laura's knowledge documents.

The product principle is separation of concerns: the backend is the brain,
Recall.ai is the meeting transport and transcript source, and the avatar vendor
is only the face and mouth. This keeps the avatar layer swappable without
rewriting reasoning, retrieval, calendar entry, or post-meeting logic.

## Current production stack

The current live backend runs on AWS App Runner in `eu-central-1`. The public
backend URL used in docs is:

`https://dhfgfe6yw6.eu-central-1.awsapprunner.com`

The current live brain provider is Groq using `llama-3.3-70b-versatile` for both
normal and fast live answers. This is a latency choice: inside a meeting, fast
first-token response matters more than long-form writing quality.

The current Recall region is EU:

`RECALL_API_BASE=https://eu-central-1.recall.ai`

Live transcription currently uses Recall's built-in low-latency English path:

`RECALL_TRANSCRIPTION_PROVIDER=recallai`
`RECALL_TRANSCRIPTION_MODE=prioritize_low_latency`
`RECALL_TRANSCRIPTION_LANGUAGE_CODE=en`

The current voice path uses the Anam persona voice. ElevenLabs is not required
for the current live meeting path.

## Runtime flow

1. A meeting entry point starts a session: manual `/join`, Chrome extension,
   calendar/Gmail watcher, or direct `POST /sessions/start`.
2. The backend asks Recall.ai to create a bot for the meeting.
3. Recall joins the meeting and renders Laura's avatar page as the bot camera.
4. Recall sends live transcript events to the backend webhook.
5. The backend decides whether Laura should answer, retrieves relevant knowledge
   chunks, and streams a grounded answer from the brain model.
6. The generated text is sent to the avatar page for speech.
7. At session end, `/sessions/{id}/end` should stop the Recall bot and avatar
   session to avoid per-minute billing.

## Owned boundaries

Answer quality is owned by:

- `avatars/laura/knowledge/*`
- `backend/app/rag.py`
- `backend/scripts/ingest.py`
- the grounding and prompt logic in `backend/app/brain.py`

Avatar rendering, voice, websocket/SSE/polling delivery, and Recall bot
configuration are separate concerns. If Laura generates a good answer but the
meeting cannot hear it, that is not a brain/RAG problem.

## Important distinction: brain problem versus delivery problem

If logs show answer latency lines or generated text but Laura does not speak,
the brain worked and the issue is downstream delivery to the avatar mouth.

If Laura speaks but gives a weak, irrelevant, or generic answer, inspect the
knowledge docs, retrieval scores, and prompt. The most common answer-quality
failure is not the LLM provider; it is missing or poorly retrieved context.

## Common questions

**"Is it still in AWS?"**
The documented production backend is AWS App Runner in `eu-central-1`.

**"What is RECALL_API_BASE?"**
It is the regional base URL for Recall.ai API calls. For this project the
documented production value is `https://eu-central-1.recall.ai`. A 401 with a
different region can mean the key and region do not match.

**"Should we change Groq?"**
Change the model only after retrieval is returning the right evidence. Groq was
chosen for live latency. A stronger model may improve reasoning, but it will not
fix missing docs, bad transcript quality, or avatar delivery.

**"Do we need ElevenLabs?"**
Not for the current live meeting path. The current voice is Anam's persona
voice, and transcription is Recall built-in low-latency English.
