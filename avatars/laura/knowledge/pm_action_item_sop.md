# SOP — Capturing and tracking action items (synthetic)

Every action item agreed in a meeting is captured with four fields: **what**
(one imperative sentence), **owner** (exactly one person — "the team" is not
an owner), **due date** (a real date; "soon" gets pushed back to the room for
a date), and **source** (the meeting it came from).

Rules of thumb:
- If a decision creates work, it creates an action item — no silent work.
- One task per outcome. "Update the deck and send it to the client" is two.
- Action items land in the team's tracker the same day as the meeting, in the
  project the work belongs to, not a catch-all inbox.
- An action item without an owner or a due date is a question for the room,
  not a task for the tracker.

Status conventions: **open** (not started), **in progress**, **blocked**
(always with a note naming the blocker), **done**. Anything blocked longer
than two working days gets raised in the next standup or chased directly.

Weekly hygiene: before the weekly sync, review items due in the past week —
done items get closed with a link to the output; slipped items get a new date
agreed with the owner, never silently moved.
